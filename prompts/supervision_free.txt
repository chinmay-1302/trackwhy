
You are evaluating the output of a Multi-Object Tracker (MOT) from a short video clip.

This is a TRACKER-ONLY visualization.

The intended target is indicated by a colored/highlighted tracker bounding box during at least the initial reliable part of the clip. Other tracker bounding boxes and track IDs are shown normally without the special highlight.

IMPORTANT: the colored highlight is primarily used to establish which PHYSICAL PERSON is the target and which tracker identity initially belongs to that person.

If the target later changes track ID, the successor track may not be specially highlighted. This is expected.

Your job is to re-associate the same PHYSICAL PERSON with ordinary tracker boxes using appearance, location, motion, expected trajectory, temporal continuity, surrounding people, occlusion reasoning, and track IDs.

Do not require the target's later box to be highlighted.

Think through the video internally before answering. Return only the final JSON.

TARGET IDENTIFICATION

First determine which PHYSICAL PERSON is the intended target from the earliest reliable highlighted portion of the clip.

Use:

* appearance,
* clothing,
* body shape,
* position,
* motion direction,
* surrounding people,
* tracker box,
* and track ID.

Once the target physical person is established, that PHYSICAL PERSON remains the target for the complete clip.

The target is NOT:

* whichever box is currently highlighted,
* whichever person has the original track ID,
* or whichever person is easiest to see.

If the original target later receives another tracker ID, continue following the same physical person under the new ordinary non-highlighted box.

If the original highlighted ID later follows another physical person, do not redefine that other person as the target.

TRACKER-ONLY HIGHLIGHT RULE

The colored highlight is a target-selection seed, not a guarantee that the target's current tracker box will always be specially marked.

After an ID switch, fragmentation, transfer, drift, or other tracker identity event:

* the target's new box may not be highlighted;
* this is expected;
* search ordinary tracker boxes for the same physical person;
* determine which tracker ID now belongs to that person;
* continue evaluating the target using that ordinary box.

The absence of a highlight on a successor track after an identity change is NOT highlight_missing.

Example:

Target person A initially has highlighted ID 43.

A becomes occluded.

The same physical person A later appears with ordinary non-highlighted ID 343.

If ID 343 represents the continuation of person A, follow ID 343 even though it is not highlighted.

This may be an identity_change such as fragmentation.

Do not classify the missing highlight on ID 343 as a probe error.

FOLLOW BOTH PERSON AND IDs

Internally maintain two kinds of continuity:

PHYSICAL CONTINUITY:
Which person is the original target?

TRACK-ID CONTINUITY:
Which physical person owns each relevant tracker ID over time?

These may separate during tracker errors.

Whenever an identity interaction occurs, explicitly determine:

1. Where is the original physical target after the event?
2. What tracker box and ID, if any, now belong to the target?
3. Where did the target's old ID go?
4. If the target has a new ID, where did that ID come from?
5. Are multiple IDs simultaneously active on the same target?

Use ordinary non-highlighted boxes as important evidence.

OCCLUSION AND RE-ASSOCIATION

Do not stop following the target when:

* the highlight disappears,
* the original tracker box disappears,
* the target becomes occluded,
* the camera moves,
* or another person crosses in front.

Use appearance before and after the event, expected motion path, position, timing, direction, and nearby people to determine which person after the event is the continuation of the original target.

Do not simply attach to the nearest visible box.

Do not simply continue following the original track ID.

The physical person defines the target.

ANNOTATION STATUS

Choose exactly one:

valid:
The physical target can be followed reliably enough to classify tracker behavior.

ambiguous:
The physical target can be identified, but the tracker event cannot be classified reliably from the visible evidence.

target_not_identifiable:
You cannot reliably establish or maintain the physical identity of the intended target.

Failure of the successor track to receive a highlight is NOT a reason to use ambiguous or target_not_identifiable.

You must re-associate the physical target even when successor tracks are not highlighted.

PRIMARY TRACKER ERROR

For valid clips choose exactly one:

no_error
miss
identity_change
drift

Do not choose no_error by default.

Check the entire target trajectory before deciding.

Use the following procedure.

DUPLICATE TRACK CHECK

First ask:

Is the SAME physical target represented by multiple simultaneously active tracker IDs?

If yes:

primary_error = identity_change
identity_change_subtype = duplicate_track

duplicate_track means two or more tracker boxes/IDs represent the same physical person at overlapping times.

Example:

Target initially has ID A.

Then ID B appears on the same target while ID A is still active.

Both tracks overlap on the same physical person.

This is duplicate_track.

The tracks do not need to be highlighted.

Inspect ordinary tracker boxes carefully.

Do not confuse duplicate_track with fragmentation.

duplicate_track:
ID A and ID B coexist on the same physical person.

fragmentation:
ID A is interrupted/lost and later the target receives ID B.

DRIFT CHECK

If there is no duplicate track, ask:

Does a track that belonged to the target begin attaching to and following a DIFFERENT physical person?

If the dominant tracker failure is a target track spatially moving or attaching onto another person:

primary_error = drift

Use:

to_moving_person:
the track drifts onto another person who is moving.

to_standing_person:
the track drifts onto another person who is standing or stationary.

IMPORTANT:

If the originally highlighted ID continues onto another person, the colored highlight may continue following that ID.

Do not follow that highlight and redefine the other person as the target.

Instead:

* continue following the ORIGINAL physical target using ordinary boxes;
* separately follow the original ID to see which person it now tracks.

A highlight following the original tracker ID onto another person can be evidence of a tracker error rather than a probe/highlight error.

IDENTITY TRANSFER CHECK

If drift does not best describe the event, check whether an EXISTING ID transfers between distinct physical people.

Use:

primary_error = identity_change
identity_change_subtype = identity_transfer

when an existing tracker ID changes physical owner.

This can happen in either direction:

* the target inherits another person's existing ID; or
* another person inherits an ID that previously belonged to the target.

Trace ID ownership explicitly.

Ask:

* Who had the target's old ID before the interaction?
* Who has that ID afterward?
* What ID does the target have afterward?
* Did the target's new ID previously belong to another person?

Example:

Before:
Target A = ID 10
Person B = ID 20

After:
Target A = ID 20

ID 20 existed before and belonged to person B.

This is identity_transfer.

Another possible transfer:

Before:
Target A = ID 10
Person B = ID 20

After:
Person B = ID 10
Target A receives another ID.

The existing ID 10 has transferred between physical people.

This can also be identity_transfer.

Do not require the target's new ID to be highlighted. It may appear only as an ordinary box.

FRAGMENTATION CHECK

Use:

primary_error = identity_change
identity_change_subtype = fragmentation

when the target's track is interrupted or lost and the same physical target later receives a newly created or restarted ID.

Typical pattern:

Target = ID A.

The target becomes occluded or loses detection.

ID A is interrupted.

The same physical target later appears with ordinary ID B.

ID B was not visibly active on another person before being assigned to the target.

This is fragmentation even if ID B is never specially highlighted.

Before choosing fragmentation, check whether ID B already belonged to another person.

If it did, consider identity_transfer instead.

If A and B overlap simultaneously on the target, use duplicate_track instead.

DRIFT VS IDENTITY TRANSFER

These may look similar.

Use drift when the dominant visible event is that the target's track/box attaches spatially and continues following another physical person.

Use identity_transfer when the dominant event is that an existing track ID changes ownership between distinct physical people.

Always inspect:

* the original physical target,
* its original ID,
* the person now carrying that ID,
* and the target's new ordinary tracker box.

If the visible evidence cannot reliably distinguish them, use annotation_status = ambiguous rather than forcing a label.

MISS CHECK

If duplicate_track, drift, and identity_change do not better explain the event, ask:

Is there a relevant interval where the physical target has no correct ordinary tracker detection/track?

If yes:

primary_error = miss

A miss may occur while the target is:

* fully visible,
* partly visible,
* heavily occluded,
* or completely hidden.

A target can still be a miss when heavily or completely occluded in this evaluation.

However, do not automatically classify every natural disappearance as miss.

If the target is tracked correctly until becoming completely unobservable and remains unobservable through the end of the clip, track disappearance alone may not be sufficient evidence of a miss.

Look at the actual timing of detection loss.

Strong miss evidence includes:

* the target remains visibly observable after the correct box disappears;
* detection disappears before complete occlusion;
* the target is visibly present before its first detection;
* the target reappears but remains temporarily undetected;
* a detection gap occurs and later the SAME ID resumes.

A detection gap followed by the same target receiving a DIFFERENT newly created ID should normally be fragmentation rather than only miss.

A missing special highlight is not a miss if an ordinary correct tracker box still exists.

NO ERROR

Only choose:

primary_error = no_error

after ruling out:

* duplicate_track,
* drift,
* identity transfer,
* fragmentation,
* and miss.

Use no_error when the physical target remains correctly tracked throughout the relevant observable trajectory.

A target may be:

* heavily occluded,
* surrounded by crowd,
* small,
* poorly localized,
* or eventually completely unobservable

without necessarily having a tracker error.

Do not interpret the expected lack of successor highlighting as an error.
